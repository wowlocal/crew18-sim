# Чёрный ящик экспедиции

Журнал доступен из приветствия и результата. Выберите забег, категорию,
событие или положение скраббера. Реплей показывает записанную траекторию,
энергию, корпус и скорость; play/pause двигает таймлайн. Опасности и записи
капитана отмечены на карте. Цитата показывается около времени записи.
Граф содержит направленные переходы экранов со счётчиками; подписи связей
доступен VoiceOver. Верхняя ссылка журнала показывает переходы по всем
сохранённым играм. JSON и текстовая сводка экспортируются системным Share Sheet.

## Архитектура

- `BlackBox` — actor с `log(level, category, message, attrs, runID, t)`.
  `seq` задаёт глобальный порядок при конкурентных вызовах, UUID обеспечивает
  идемпотентность записи, schemaVersion = 1. Ошибки дублируются в OSLog
  подсистемы `io.podlodka.dive`; сбой хранилища не выбрасывается в движок.
- `BlackBoxRecorder` сохраняет порядок Combine через последовательную цепочку
  задач. На пути симуляции нет дискового I/O. `SituationSummary` содержит
  read-only копии позиции, энергии и корпуса; каждый четвёртый `.situation`
  становится снапшотом. Старт и финал имеют отдельные защищённые снапшоты.
- `BlackBoxStore` — SwiftData `@ModelActor`, отдельный контекст. Сброс по 64
  записям или каждые 3 секунды. Часы и ожидание можно внедрять в тестах.
  Ошибка транзакции откатывает контекст, буфер остаётся для повторной попытки.
- `BlackBoxReader` — страницы по `seq`, максимум 512 записей; UI читает страницы
  и собирает их для реплея/экспорта. Список забегов сохраняет последние 10.
- В фоне предоставляется системное время на сброс. Старт без финала после
  перезапуска получает единственный `run.end` с outcome `interrupted`.
  События последних трёх секунд могут исчезнуть при принудительном завершении
  процесса до сброса: это ограничение пакетной записи.

Покрываются события движка: находки, мины, щит/урон, портал/спрут, ресурсы,
цель, победа и рекорд; состояние, управление, экраны, гараж, фон приложения.
Отказы способностей содержат state/cooldown/energy, гаража — state/crystals,
швартовки — speed. Ошибки декодирования/кодирования гаража записываются отдельно.
Новые диагностические события не меняют accessibilityAnnouncementRevision,
таймеры, RNG и физику. VoiceOverAnnouncer игнорирует диагностику.

## Голос

Микрофон в HUD запускает on-device SFSpeechRecognizer с локалью устройства;
второй тап завершает запись. Игра продолжает работать. В БД попадает только
текст с runID и временем начала диктовки. Частичные результаты видны в HUD.
При отсутствии разрешений или поддержки локальной модели показано объяснение;
сетевой fallback не включается. Протокол `VoiceNoteTranscriber` позволяет
проверять конвейер без микрофона. Речь и системные диалоги разрешений нужно
проверить на физическом устройстве (ru/en).

## Границы реализации

- Лимит буфера 512 применяется с вытеснением только debug/частых снапшотов.
  Если хранилище недоступно и буфер состоит исключительно из защищённых
  событий, лимит мягкий: память может расти, чтобы не выбрасывать эти события.
  Обещать одновременно жёсткий лимит и отсутствие потерь при постоянном
  отказе диска невозможно.
- Реплей визуализирует телеметрию, а не повторно запускает физику. Корпус
  дискретный; позиция, энергия и скорость интерполируются. Карта использует
  стандартную геометрию экспедиции и отдельные координаты пещеры; траектория
  не интерполируется через переход между зонами. Мир предметов/мин в прошлом
  не реконструируется.
- `t` — активное игровое время с начала забега (пауза его не увеличивает); события меню
  имеют отдельный sessionID, связанный с последующим забегом,
  `wallTime` — календарное время записи. Снапшоты поступают только при игре.
- В UI доступны все категории; сообщения событий сохраняются на языке игры.
  Новые элементы интерфейса локализованы в String Catalog ru/en.
- Переполнение при постоянном отказе диска и процесс, убитый до первого
  сброса, не имеют гарантии восстановления. Аудио никогда не сохраняется.

## Проверки

Новые unit-тесты проверяют порог 64, таймер с внедрённым ожиданием, 600
конкурентных событий, отсутствие дублей, пагинацию, JSON/runID, переоткрытие
файловой БД, retention/interrupted, отказы способностей, снапшоты, интерполяцию,
конвейер капитанской записи и scripted navigate() с точным порядком событий.
UI-тест открывает журнал и реплей, перематывает скраббер и выполняет
`performAccessibilityAudit()`. Старые игровые и UI-тесты остаются в suite.

`python3 scripts/sync-dactyl.py` включает оба новых файла; нативный проект
содержит источники и оба permission-ключа. Для Dactyl-хоста также нужны
разрешения микрофона и распознавания речи в его Info.plist.
